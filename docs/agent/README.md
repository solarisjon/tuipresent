# Agent documentation for tuipresent

These files are for LLM agents that write, check or answer questions about tuipresent decks. They describe the code as it is, quirks included.

## Read order

1. **Writing a deck from a brief:** start with [docs/agent-skill/SKILL.md](../agent-skill/SKILL.md) (condensed workflow and rules), then [docs/AGENT_GUIDE.md](../AGENT_GUIDE.md) (full workflow, verification steps, layout budget, design guidance, pre-handoff checklist). Consult LANGUAGE.md for any construct you are unsure about.
2. **Answering a precise question about the syntax or layout** (what does X parse to, how many rows does Y take, why did Z vanish): go straight to [LANGUAGE.md](LANGUAGE.md), then confirm with the matching case in [EXAMPLES.md](EXAMPLES.md).
3. **Validating front matter in an editor or tool:** [frontmatter.schema.json](frontmatter.schema.json).

## Relationship between the docs

- **LANGUAGE.md** is the normative specification: rules, regexes, formulas, edge cases. It does not tell you how to design a talk.
- **EXAMPLES.md** is evidence: each case is a minimal deck plus its real `-check` line and `-dump` frames. It is generated by `gen_examples.py` in this directory; rerun it after any parser or renderer change (`go build -o bin/tuipresent ./cmd/tuipresent && python3 docs/agent/gen_examples.py`) and review the diff. The script never passes `-exec`.
- **AGENT_GUIDE.md** is the workflow guide: requirements, outline, verification commands, budgets and rules of thumb, design guidance, an annotated deck and a checklist.
- **SKILL.md** is the condensed skill for agent runtimes that load skills; it points back to AGENT_GUIDE.md.
- **docs/guide/** is the human user guide.

If two documents disagree, the code wins. LANGUAGE.md and EXAMPLES.md are the most precise; fix the others (or report the drift).

## Ground rules for agents

- Always build and run `-check` and `-dump` at 80x24 and 100x30 before handing off a deck (AGENT_GUIDE.md §2).
- Never pass `-exec` without the user's approval: it runs the deck's code.
- Every authoring mistake except bad YAML degrades silently (LANGUAGE.md §16.3). Read the dump.
